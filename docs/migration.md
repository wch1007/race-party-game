# 从 Godot 到 Three.js

依据：上级工程 README、GDD、角色和赛道数据，以及“在godot上实际跑当前文件夹里的项目，debug，实际跑通。（允许你监控画面）”对话的最新要求。

## 确认的规则

2026-09-29，用户确认采用四人各跑一段、共一圈 100 格的接力。24／49／74 为交接点，精确停到交接点奖励额外回合；跨过时正常交棒。解决旧程序在所有角色都从 0 开始的情况下，接力判断缺失等待位置、某些区域连续交棒的问题。

保留 40 人角色定义、同局随机十人候选、2–4 队、同队去重跨队可重复、角色实例独立冷却、100 格数据、后置干预、固定角度平移缩放和角色相遇对话。联机由 ENet 迁移到 WebSocket 权威服务。

事件格遵循 GDD“效果提前可见、无隐藏抽奖”的要求，按格子编号预设 ±1，并显示到格面上。旧导演脚本的随机事件不继续保留。后退在起点截断，避免 0 后退变 99 格。

## 骰子

没有声称浏览器刚体模拟一定做不到，而是本次直接采用用户允许的概率方案：保持六面空间朝向与连续翻面动画，让控制感来自实时预览和力度时机。视觉动画不反过来决定规则；浮点误差不会制造判面漂移。

基础点数由均匀抽取 24 个合法朝向产生，吹风和振桌根据力度分布决定转过 0–3 面。可以注入种子复现一场对局。网络服务器在自己的时钟上拒绝过期干预并限制每队动作次数。

## 第一版的边界

- 程序生成手办和桌面美术，尚未加入精细外部角色模型和完整装扮库存。
- 支持浏览器本地游戏和自行启动服务的房间联机，没有公共匹配服务、Steam SDK 或原生手机包。
- 盘内约束动画，不模拟真实出盘、物理碰撞、麦克风、陀螺仪。
- 支持单个 W/A/S/D 方向，未实现旧工程的组合斜向风。
- 联机各自选择阵容，默认预填可玩阵容；尚未迁移 30 秒轮流选角和断线重连。
- AI 使用合法随机投骰和基础技能策略，不会偷看未来随机数。
